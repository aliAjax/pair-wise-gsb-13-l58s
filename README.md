# 加油站班次交接 · 按价格段拆账

班中调价后，营业员不再只记一个整班均价：一个班次可以记多个**油品价格段**，
每段填写起止泵码与单价；同油品同泵相邻段**泵码接不上就留在待修正**，
修正前不能送复核。现金、电子支付与各段应收自动汇总，**有长短款必须写明原因**
才能送站长复核；复核通过后整班**冻结成只读凭证**，再次打开只能带原因订正，
并在凭证内保留旧金额与订正时间。

## 运行

零依赖、零构建，两种方式任选：

```bash
npm start          # Node 内置模块起静态服务 → http://127.0.0.1:8931
# 或直接双击 index.html（普通 script 标签，file:// 也可运行）
```

## 代码分层（页面交互 / 规则 / 本地存储分开）

| 文件 | 职责 | 是否碰 DOM | 是否碰 localStorage |
| --- | --- | --- | --- |
| `js/rules.js` | 业务规则纯函数：泵码接续校验、分段计价、应收/实收/长短款汇总、送复核校验、送审/退回/冻结/订正状态机、金额快照 | 否 | 否 |
| `js/storage.js` | 班次凭证、当前身份、编辑草稿的读写；凭证编号；种子数据 | 否 | 是 |
| `js/app.js` | 路由、列表与表单渲染、事件绑定、调用规则层与存储层 | 是 | 否（经 Storage） |
| `index.html` / `styles.css` | 结构与样式，无任何外部字体/图片/库依赖 | — | — |

规则层可单独用任意 JS 运行时调用；以后换成接口校验时，只需新增同名数据适配层。

## 关键业务规则

1. **价格段**：每段 = 油品 + 泵号 + 起始泵码 + 止码 + 单价；数量 = 止码 − 起始码，应收 = 数量 × 单价。
2. **接续校验**：同油品同泵的价格段按起始码排序，相邻段必须首尾相接；起始码 ≠ 上段止码即标记「待修正」，整班不能送复核。
3. **必填校验**：班次日期/班次/营业员、各段全部字段、现金与电子支付金额均不能为空或非法；止码不能小于起始码；空白段必须补全或删除。
4. **长短款**：长短款 =（现金 + 电子支付）− 应收合计；差异 ≠ 0 时必须填写原因，否则不能送复核。
5. **复核冻结**：站长通过后整班生成凭证编号（PZ-年月日-序号）并冻结为只读；退回必须填写意见，退回后回到可修正状态。
6. **订正留痕**：对冻结凭证只能「发起订正」（必填原因）；订正需再次送复核，通过后重新冻结；每次订正保留订正前的金额快照（现金、电子支付、应收、长短款、各价格段明细）与旧时间，新老差额在「订正记录」中对照展示；放弃订正可按冻结快照恢复。
7. **金额口径**：所有金额内部以整数「分」存储与计算，避免浮点误差；泵码按升计、最多两位小数。

## 数据

全部保存在浏览器 `localStorage`：

- `gas-shift-handover:v1`：班次凭证
- `gas-shift-handover:drafts:v1`：编辑中的草稿（录入实时保存，刷新不丢）
- `gas-shift-handover:role`：当前身份（营业员 / 站长）

首次打开内置 3 个演示班次：一笔已冻结且有一次「通过的订正」（旧短款 100 元留痕）、
一笔班中柴油调价且带长短款原因的待复核班次、一笔泵码差 0.5L 留在待修正的草稿。
